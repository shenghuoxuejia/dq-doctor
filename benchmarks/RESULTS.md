## 1. 案例研究：删哪一列由工具决定

脚本里**没有出现泄漏列名的字面量**：`scan_leakage()` 先给出候选，下游 `drop()` 用的就是它的返回值。

| 项目 | 结果 |
| --- | --- |
| 数据规模 | 1000 行 × 16 特征（15 个基础特征 + 1 条事后字段） |
| 工具标记为泄漏的特征 | `post_event_status` |
| 脚本是否硬编码列名 | **否**——删除列表来自工具返回值 |
| 5 折交叉验证 AUC（含泄漏特征） | 1.000 |
| 5 折交叉验证 AUC（按工具建议剔除后） | 0.910 |
| 虚高幅度 | **0.090** |

**结论**：这条事后字段让离线 AUC 虚高 0.090。它在事件发生之后才写入，线上预测时不可得，属于典型的 target leakage。DQ-Doctor 在没有被告知任何线索的情况下独立命中。

## 3. 第一类错误率（蒙特卡洛，400 次重复）

每次重复独立生成数据，统计在零假设成立时误报的比例（400 次重复）：

| 检验 | 名义水平 | 实测第一类错误率 | 解读 |
| --- | ---: | ---: | --- |
| Little's MCAR（10 列，15% MCAR 缺失） | 5% | **3.5%** | 低于名义水平，p 中位数 0.46，检验偏保守 |
| 泄漏扫描 AUC ≥ 0.95（20 个白噪声列，n=200） | — | **0.0%** | 纯噪声完全够不到 0.95，零误报 |
| 同上，阈值降到 0.90 | — | 0.0% | 仍未误报：n=200 下噪声列最大 AUC 的 95 分位只有 0.625，远低于 0.90 |
| 同上，阈值降到 0.85 | — | 0.0% | 仍是 0 误报：20 个噪声列仍然够不到阈值 |
| 同上，阈值 0.95 但样本量降到 n=60 | — | 0.0% | 阈值仍未被击穿，但噪声 95 分位从 0.625 抬到 0.723，余量明显收窄 |

20 个噪声列中最大的单特征 AUC：中位数 0.588，95 分位 0.625。**0.95 高于 n=200 时的噪声天花板**，所以它在"不误报"这一侧是安全的——真正的代价落在另一侧：`real_cancer.csv` 的合法强特征被误报（第 2 节），以及 0.92 左右的真实泄漏会被漏掉。换句话说，这个阈值偏保守，宁可漏检也不冤枉，应按业务代价重新标定。样本量降到 n=60 时噪声 95 分位抬到 0.723，阈值余量随之收窄，所以解读这个阈值时必须带上样本量。

## 4. 同源特征聚类去重

单一阈值会把同一族高度相关的特征全部报出来，对用户是噪音。`scan_leakage()` 用 |ρ|>0.9 做聚类，只保留组内 AUC 最高的代表：

- 原始候选（逐个算 AUC）：**5 个** —— `mean concave points`、`worst radius`、`worst perimeter`、`worst area`、`worst concave points`
- 聚类后输出：**2 个** —— `worst perimeter (0.975)`、`worst concave points (0.967)`
- 噪音降低 60%，且没有丢掉最强信号
